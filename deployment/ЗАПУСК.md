# Запуск сборки в техникуме

Сборка от 26.10.2026 содержит исходники, vendor (PHP-зависимости), готовый public/build и дамп текущей MySQL. Composer и Node.js для запуска этого архива не нужны. PHP и MySQL в архив не включены.

1. На компьютере нужны PHP 8.4.1–8.5.x и MySQL 8.x. PHP должен быть в PATH, расширения: pdo_mysql, mbstring, openssl, fileinfo, dom, xml, xmlwriter, bcmath, gd, tokenizer, ctype, session. Запустите службу MySQL.
2. Распакуйте архив в отдельную папку, например C:\vegetable-base. Откройте терминал в папке с artisan.
3. Выполните `php deployment/setup.php`. При первом запуске он создаст .env из шаблона и остановится для настройки.
4. Откройте .env в редакторе. Укажите DB_HOST, DB_PORT, DB_DATABASE (новая база), DB_USERNAME и DB_PASSWORD от MySQL этого компьютера. Пользователь должен иметь права создания базы/таблиц и записи. Для заранее созданной базы нужны права на неё.
5. Заполните внешние сервисы:
   - SMTP: MAIL_HOST, MAIL_PORT, MAIL_USERNAME, MAIL_PASSWORD (пароль приложения почты), MAIL_FROM_ADDRESS. MAIL_SCHEME=smtp для 587 (STARTTLS), smtps для 465. Это отдельные настройки почты, а не ключ геокодера.
   - Яндекс: YANDEX_GEOCODER_API_KEY для серверного геокодера и YANDEX_MAPS_API_KEY для карты. Подключите соответствующие API и разрешите адрес сайта в настройках ключей.
   - ЮKassa: YOOKASSA_SHOP_ID и YOOKASSA_SECRET_KEY тестового магазина, YOOKASSA_TEST_MODE=true. Обычный ключ рабочего магазина не становится тестовым от этого флага.
6. Повторите `php deployment/setup.php`. Он импортирует дамп только в пустую базу, создаст новый APP_KEY, выполнит недостающие миграции, подготовит каталоги и ссылку изображений. Существующие таблицы не заменяются. При прерванном импорте укажите другое имя новой базы и повторите настройку.
7. Запустите `php artisan serve --host=127.0.0.1 --port=8000` или deployment/start.cmd. Откройте http://127.0.0.1:8000. Терминал должен оставаться открытым.

Учётные записи и пароли сохранены из текущей базы. Сидеры запускать не нужно: они могут сбросить пароли. При утрате пароля используйте восстановление через настроенную почту. Учебные учётные записи описаны в README; их наличие и пароль зависят от текущего дампа.

После изменения .env выполните `php artisan config:clear`. Для локальной проверки без почты можно временно задать MAIL_MAILER=log — письма появятся в storage/logs/laravel.log, но отправляться не будут.

Для webhook ЮKassa нужен доступный извне HTTPS-адрес /payment/webhook; localhost недоступен сервису. При использовании внешнего адреса измените APP_URL и настройте HTTPS. На локальном сайте состояние оплаты можно повторно запросить кнопкой проверки. Ключи, доступ в интернет и настройки провайдеров нужны для реальной проверки интеграций; в архиве нет действующих секретов.

Дамп deployment/database.sql — копия текущей БД, включая пользователей и историю. Не публикуйте архив или SQL в открытом репозитории. При установке очищаются перенесённые сессии и одноразовые коды; старые банковские данные из неиспользуемой таблицы user_cards новый сайт не читает. Новый APP_KEY не предназначен для расшифровки старой таблицы.

Фотографий в storage/app/public и private на момент упаковки не было; витрина использует заглушки, где фото отсутствуют. Добавьте реальные изображения через административную панель.

Если ошибка TLS: настройте доверенные CA-сертификаты PHP (openssl.cafile/curl.cainfo); отключать проверку сертификатов не нужно. Если PHP не найден — добавьте его каталог в PATH или используйте полный путь к php.exe. При занятом порте выберите другой порт и измените APP_URL.
